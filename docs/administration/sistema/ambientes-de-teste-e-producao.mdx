## Para que serve?

Explica a diferença entre a base onde se experimenta e a base onde a empresa trabalha a sério, e o que garante que **nada do que se faz em teste chega à Autoridade Tributária (AT), aos bancos ou aos clientes**. Serve para formar pessoas, experimentar uma versão nova ou reproduzir um problema sem risco.

## Quando utilizar?

- Vai formar alguém ou experimentar uma versão nova.
- Quer ter a certeza de em que ambiente está antes de fazer um envio.
- Vai passar a empresa para produção.

## Onde encontrar?

Não há um menu para isto. O ambiente vê-se:

- no **nome da base de dados**: uma base de testes tem «test» no nome;
- em **Contabilidade › Configurar › Faturação certificada › Credenciais da AT**, na coluna **Ambiente**, para os envios à AT.

## Antes de começar

O menu **Credenciais da AT** só aparece a quem tem esse direito. Foi percorrido com o perfil **Administrador**. O **Contabilista certificado** não tem este menu. Se não souber o nome da base de dados, pergunte ao suporte técnico.

## O que muda numa base de testes

| | Base de testes | Base de produção |
|---|---|---|
| **Nome da base de dados** | Tem «test» | Não tem «test» |
| **Dados** | Inventados | Reais |
| **Comunicação à AT** | Só o simulador local, com as mensagens dos manuais da AT | A que o responsável ligar de propósito |
| **Rede** | Só a própria máquina: o resto é bloqueado antes de sair | Normal |
| **Correio, bancos, SIBS, pagamentos** | Nunca | Se estiverem ligados |
| **Quem assina os documentos** | Uma fiscaldoo simulada, com uma chave fictícia e o certificado 9999: os documentos não servem para nada na lei | A fiscaldoo verdadeira, com a chave de API da instalação |
| **Valor fiscal dos documentos** | Nenhum | Total: corrigem-se com nota de crédito, e não se apagam |

A separação está **no servidor**, e não só no ecrã: ninguém a contorna por engano, nem com um clique. Visto no ecrã: o simulador da AT e a fiscaldoo simulada, que numa base de testes diz «Base de teste: uma fiscaldoo simulada assina com uma chave fictícia e o certificado 9999.» ([Como ligar a instalação à fiscaldoo, que assina os documentos](/fiscal-core/chaves-de-assinatura)). <span className="fd-pending">Pendente de validação no ecrã: as outras linhas (rede, correio, bancos, SIBS, pagamentos), que vêm do guia de operação.</span>

## O que decide para onde segue um envio à AT

<StepByStep>

1. Abra **Contabilidade › Configurar › Faturação certificada › Credenciais da AT**. Cada linha tem **Empresa**, **Ambiente**, **Utilizador do webservice**, **Usado para envio** e **Válido até**.
   ![Lista Credenciais da AT com uma linha da empresa de demonstração, no Ambiente Teste, com validade até 31/10/2031 e o utilizador tapado](/images/administration/ambientes-de-teste-e-producao/01-credenciais.png)
2. Abra a ficha. O campo **Ambiente** tem duas opções: **Teste** e **Produção**. Uma ficha nova começa sempre em **Teste**.
3. Só o **Ambiente** e a marca **Usado para envio** decidem para onde segue um envio. Com as credenciais de teste, a ficha oferece **Testar a ligação (simulador)** e **Ver a prontidão**.

</StepByStep>

## Passar para produção

É uma operação da base de produção, com o suporte técnico. Na ficha de **Credenciais da AT**: escolha **Produção**, escreva o **Utilizador do webservice** e a **Palavra-passe do webservice**, carregue o certificado que a AT enviou e marque **Usado para envio**. Um conjunto por empresa e por ambiente. Depois de gravados, os segredos aparecem tapados e só se podem substituir.

Este caminho não foi feito até ao fim na demonstração, porque exigiria credenciais reais. Pendente de validação no ecrã.

## Notas importantes

- **Nunca copie dados reais para uma base de testes** sem os neutralizar antes (nomes, NIF, contactos, IBAN).
- **Para reproduzir um problema**, restaure uma cópia numa base nova com «test» no nome. Para o planeamento de cópias e ensaios, veja [Como preparar a migração de outro programa para o fiscaldoo](/migration-toolkit/planear-a-migracao).
- **Uma base de testes assina com a fiscaldoo simulada, nunca com a de produção.** A chave privada de produção nunca sai da fiscaldoo, e a chave de API só assina para a base com que foi registada. Por isso uma cópia de produção restaurada numa base com «test» no nome passa a assinar com a fiscaldoo simulada. <span className="fd-pending">Pendente de validação no ecrã: que a chave de API só assina para a base registada e que a cópia de produção restaurada passa a assinar com a simulada (só se viu a fiscaldoo simulada numa base de testes; a demonstração não chega à fiscaldoo verdadeira).</span>
- **Resultados simulados.** Em teste, os resultados aparecem como simulados, por exemplo **Aceite (simulado)**, com o **Ambiente** **Teste**.
- **O que este artigo não cobre.** Um servidor de testes ligado aos endereços de testes da AT é uma operação do suporte técnico, e não uma configuração do utilizador.

## Problemas frequentes

### Mensagens de recusa

Estas mensagens são o isolamento a funcionar. Pendente de validação no ecrã: não foram provocadas na demonstração, porque seria tentar um envio à AT de produção.

- **«O ambiente de produção da Autoridade Tributária não é permitido numa base de dados de teste. Não foi enviado nada. Escolha as credenciais de teste da empresa …»:** escolha as credenciais de teste, ou faça o envio real na base de produção.
- **«A empresa … ainda não escolheu o ambiente da AT. Assinale «Usado para envio» nas credenciais de teste ou de produção …»:** abra **Credenciais da AT**, escolha o conjunto e marque **Usado para envio**.
- **«As credenciais partilhadas são de outro ambiente (teste ou produção).»:** use o conjunto do ambiente da empresa. Não reutilize as de produção em teste.
